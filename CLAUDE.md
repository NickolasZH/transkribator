# Transkribator

Транскрибация аудио в текст. Пользователь — аналитик, не программист:
объясняй простым языком, не предполагай знания git/тестов/паттернов.

## Сначала прочитай

- `README.md` — что за проект, как запускать, локально и на сервере.
- `CHANGELOG.md` — журнал разработки. Смотри последние записи перед
  содержательной работой, чтобы не наступать на те же грабли повторно
  (например, история с прокси и sudo при настройке сервера).

После заметных изменений добавляй запись в `CHANGELOG.md` (дата, что
сделано, почему). Список известных грабель веди там же, не переоткрывай.

## Устройство

- `transcribe.py` — вся логика в одном файле, командная обёртка на
  `argparse`. Пока проект маленький — дробить на модули рано.
- `records/` — аудио и готовые `.md`-транскрипты. Не в git: там реальные
  записи совещаний, потенциально чувствительные.

## Два окружения

1. **Локально, Windows**: conda-окружение `asr`
   (`C:\Users\nicko\anaconda3\envs\asr`). Активируется `conda activate asr`.
2. **Сервер, Linux Mint** (`<SERVER_USER>@<SERVER_HOST>:<SERVER_PORT>`): venv в
   `~/python_projects/transkribator/.venv`, без conda. На сервере нет прав root — venv
   создан в обход `ensurepip` (см. `CHANGELOG.md`), pip доустановлен через
   `get-pip.py`. Не пытайся ставить пакеты через `apt` без прямого запроса
   пользователя ввести пароль sudo самостоятельно — пароли за пользователя
   не вводи.

Типичный рабочий сценарий: пользователь присылает аудиофайл в чат,
Claude заливает его на сервер по `scp`, запускает `transcribe.py` там
(сервер быстрее ноутбука), забирает готовый `.md` обратно.

## Осторожно

- На Windows-ноутбуке в реестре включён локальный SOCKS-прокси
  (`socks4://127.0.0.1:10808`), который ломает pip/huggingface_hub без
  пакета `pysocks`. В `transcribe.py` уже есть обход (см. начало файла,
  срабатывает только при `os.name == "nt"`) — трогать без причины не надо.
- Не выводи содержимое `records/*.md` в чат целиком без запроса — там
  могут быть записи внутренних совещаний.
- SSH-ключ для сервера — `~/.ssh/id_rsa` (уже в `~/.ssh/config`, если
  добавляли). Пароли/passphrase не запрашивай и не вводи.

## Работа с изменениями

Git локальный, репозиторий только на этом ноутбуке, remote нет.
Перед сериями правок — смотри `CHANGELOG.md`, обновляй его по ходу дела.
